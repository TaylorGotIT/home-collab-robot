# 01 · 可行性分析

> 结论先行：**技术上可行，商业上成立，但有三个必须接受的前提**（见文末）。真正的风险不在"能不能做出来"，而在"做出来谁用、出了事谁担"。

## 一、怎么评级

用两个维度打分，避免"什么都想做"：

- **技术成熟度**：成熟（有现成货架产品）/ 较成熟（有产品但要集成）/ 可用（实验室能跑，现场不稳）/ 早期（demo 级）/ 不成熟（无可靠方案）
- **落地优先级**：P0（V1 必须）/ P1（V1.5）/ P2（V2）/ P3（V3）/ —（不做）

星级 = 综合"技术可达性 × 场景价值 × 风险可控性"，5 星为"现在就能交付且用户愿意付钱"。

## 二、总体结论

| 维度 | 结论 | 信心 |
| --- | --- | --- |
| 技术 | 室内移动 + 远程接管 + 简单抓取，**24 个月内可工程化** | 高 |
| 技术 | 爬楼、搀扶，**可做但必须限定边界**，且是可靠性长尾 | 中 |
| 技术 | 全自主上门、上街买菜，**3 年内不具备交付条件** | 高 |
| 商业 | 工作场景（网络安装）**ROI 明确**，单次成本可降到人工的 1/4–1/2 | 中高 |
| 商业 | 家庭场景**付费意愿存在但单价敏感**，适合租赁而非买断 | 中 |
| 合规 | 认证路径清晰（6 个月、90 万元），但**数据与责任是长期负担** | 中高 |

## 四、技术可行性（分项论证）

### 4.1 移动底盘与爬楼

**方案选择**：四轮独立驱动 + 前支撑摆臂 + 可切换行星轮组。备选是摆臂履带（稳但慢、伤地板、室内不友好）和双足/轮腿（控制难、成本高、跌倒风险大）。

**关键估算**：

| 指标 | 估算 | 依据 |
| --- | --- | --- |
| 整备质量 | 75 kg（含货架电池） | 底盘 45 + 臂 12 + 电池 12 + 结构 6 |
| 爬楼垂直速度 | 0.15 m/s | 单级 170mm 约 1.5–2s |
| 爬一层（18 级）耗时 | 3–6 min | 含平台转向、对准、安全停顿 |
| 平均功率 | ≈ 75 W | P = m·g·v = 90×9.8×0.085 |
| 峰值功率 | 300–400 W | 平均的 4–5 倍 |
| 电机总额定 | 4 × 250 W = 1 kW | 裕度 2.5 倍，够 |
| 静态稳定角 | ≈ 26.6° | arctan(轮距/2 ÷ 质心高) = arctan(0.275/0.55) |

**结论**：爬楼技术上成立，但 **30° 坡道已接近静态稳定极限**——所以设计上限必须写死为"坡度 ≤30°、单级 ≤180mm、必须有扶手或墙体一侧、必须有人在场"。质心再高 5cm，稳定角就掉到 24°，这是硬约束，不是优化项。

### 4.2 机械臂与抓取

**方案选择**：6 自由度、负载 5kg、臂展 750mm 的轻量协作臂 + 二指电动夹爪。原型外购（睿尔曼/越疆级），小批起自研降本。

**精度预算（这是"能不能插网线"的答案）**：

| 误差源 | 开环量级 | 说明 |
| --- | ---: | --- |
| 底盘定位误差 | ±30 mm | SLAM 精度上限 |
| 臂运动学误差 | ±1 mm | 重复定位 ±0.1mm，绝对精度差 |
| 手眼标定残差 | ±2 mm | 标定后可保持 |
| 目标检测误差 | ±10 mm | 2D 检测框 + 深度噪声 |
| **开环合计** | **±35 mm** | 远大于 RJ45 插座的 ±1.5mm 容差 |
| **视觉伺服闭环后** | **±2 mm** | 需要 30–60 帧迭代 |

**结论**：**开环抓取只能做"大件"（放路由器、拿快递箱、递水杯）；插网线这类精密动作必须闭环 + 柔顺**（导角、RCC、力觉搜索、允许失败重试 3 次）。这把"机器人自己插线"从"不可能"变成"慢但能成"，也解释了为什么 C-09 只能给 ★★★★☆ 而不是五星。

### 4.3 远程接管与遥操作（本项目最关键的一节）

**时延预算（4G 公网，端到端）**：

| 环节 | 时延 | 备注 |
| --- | ---: | --- |
| 相机采集 + 曝光 | 33 ms | 30 fps |
| H.264 硬编码 | 15–25 ms | |
| 上行单程 | 40–70 ms | 4G 上行 20–50 Mbps |
| 云端中转 | 5–15 ms | 就近接入 |
| 下行单程 | 40–70 ms | |
| 解码 + 渲染 | 16–30 ms | |
| **合计** | **150–240 ms** | 5G 专网可压到 60–110 ms |

**人体工程学阈值**：直接遥操作的可接受上限约 100–150 ms；超过 200 ms 操作者明显感到"拖沓"；超过 300 ms 精细操作基本失效。

**结论（本项目的核心设计决策）**：

> 纯遥操作只能承担"粗动作"——移动、观察、搬运大件。
> 精细动作必须走 **共享控制**：人给意图（"插这个口"），机器做视觉伺服与力控闭环（本地 30–100 ms 内完成）。
> 这决定了软件架构必须是"云-边-端三层"，而不是"视频流 + 摇杆"。

这条结论直接影响三件事：BOM 里必须保留边缘算力（Jetson Orin 级）、算法团队必须有视觉伺服能力、试点验收指标必须是"任务成功率"而不是"视频清晰度"。

### 4.4 自主导航与定位

- 室内 3D SLAM 定位精度 ±5cm，配合反光板/UWB 可到 ±2cm（成本 +3000 元，暂不做）。
- 玻璃门、白墙、强光地面是三个典型失效场景 → 靠"激光 + 深度 + 超声 + 防跌落"四重冗余 + 失效降级（限速 0.2 m/s 或停车）。
- **跨楼层是死结**：国内绝大多数电梯无开放接口，云呼梯改造需物业配合（单栋 3000–8000 元）。这直接从工程上否定了"全自主上门"——不是算法不行，是电梯不给你控制权。

### 4.5 电源与续航

| 工况 | 功率 | 主电池 48V/24Ah（1.15 kWh）续航 |
| --- | ---: | ---: |
| 待机/陪伴 | 80 W | 14 h |
| 平地巡航 | 250 W | 4.6 h |
| 混合（走 + 臂 + 屏） | 350 W | 3.3 h |
| 爬楼 | 500 W | 2.3 h |
| 叠加货架电池 48V/30Ah（+1.44 kWh） | — | 混合工况约 6–7 h |

**结论**：室内一天够用；园区巡检一天够用；**"上街买菜"往返 3km + 负重 + 等待，需要 8h 以上，属于 V3 议题**。货架电池的 220V/500W 逆变是差异化功能（给用户的手机、路由器、甚至电饭煲供电），成本仅 4600 元，建议保留。

### 4.6 交互

语音唤醒 + 大屏 + 远程接管三通道。老人场景的真实约束不是识别率，而是**方言、听力下降、不愿意"对机器说话"**。所以 V1 的交互主路径是"子女远程接管 + 老人看着屏幕说话"，语音是辅助而非唯一入口。

## 六、商业可行性

**工作场景（单城市模型，可验证、不依赖宏观数据）**：

- 一个二线城市的中型宽服商，日均 300 单上门，单均 500 元 → 年支出 5,475 万元。
- 若 30% 标准化订单由机器人完成，年节省约 1,100 万元；即使只替代 10%，也是 550 万元。
- 机器人侧：6 台设备投入 39 万元，年运营成本约 44 万元 → **首年即打平，第二年净省**。

**家庭场景**：

- 支付方是异地子女，不是老人本人。决策链路短、情感驱动强，但对"值不值 1000 元/月"极敏感。
- 因此家庭场景的正确形态是**租赁 + 服务包**（1200 元/月含设备、运维、7×24 接管），而不是 6.5 万元买断。
- 家庭场景的真实价值不在硬件毛利，而在**接管服务时长**与**后续上门服务导流**。

## 七、合规与安全可行性

| 事项 | 结论 |
| --- | --- |
| 无线电（WiFi/4G） | 必须做 SRRC 型号核准；若用已核准模组可大幅简化 |
| 电气安全 | 按 GB 4943.1 做安规；是否落入 CCC 目录需按最终产品归类确认 |
| 电池 | GB 31241 + UN38.3 运输认证 |
| 机械安全 | GB/T 39785 服务机器人机械安全评估与测试方法 |
| 数据 | PIPL/DSL + 儿童个人信息规定；视频默认不留存、端到端加密 |
| 道路 | 无明确法规 → 只做园区/社区内部，不碰公共道路 |
| 责任 | 产品责任险 + 用户协议边界 + 全链路日志可追溯 |

全部认证预算 90 万元、周期 6 个月，可与 C 样并行，但**不能压缩**。

## 八、结论：可行性成立的条件

技术可行、商业可算，但只在同时满足以下五条时成立：

1. **产品定义降维**：远程接管为主、自主为辅，不承诺"全自主"。
2. **场景排序**：先工作（网络安装/园区巡检），后家庭（陪伴/协助）。
3. **边界写死**：爬楼限坡度与台阶、搀扶限监护、入室限有人在场，且写进合同。
4. **软件优先**：预算里算法与云平台占比不低于 40%，不把钱全砸在结构上。
5. **认证前置**：B 样就开始预测试，不接受"C 样再补"。

任一条不满足，建议把项目缩回"园区巡检机器人"单场景版本（投入可降到 800 万元、12 个月），先活下来。
