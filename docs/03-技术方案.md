# 03 · 技术方案

> 一句话架构：**云-边-端三层，端上做实时与安全，云上做接管与调度，边（本体算力）做视觉伺服**。
> 设计原则：**宁可少一个功能，不可少一条安全回路。**

## 一、总体架构

```
┌───────────────────────────── 云端 ─────────────────────────────┐
│  设备接入网关 │ 会话与权限 │ 录像与审计 │ OTA │ 订单调度 │ 计费    │
└───────────────┬────────────────────────────────────────────────┘
                │  WebRTC：媒体通道 + 控制通道（DTLS-SRTP 加密）
        ┌───────┴────────┐
        │ 4G/5G · WiFi6  │  ← 双链路，秒级自动切换，断网本地自治
        └───────┬────────┘
┌───────────────┴───────────────── 本体 ─────────────────────────┐
│ 计算层 │ Jetson Orin NX：感知 / 规划 / 视觉伺服 / 视频编码         │
│        │ STM32H7：1 kHz 实时运动控制 + 独立安全回路（独立供电）    │
│ 感知层 │ 3D LiDAR · 深度相机×2 · 超声×8 · 防跌落×4 · IMU · 轮速    │
│ 执行层 │ 4×轮毂电机 · 行星轮爬楼 · 6DOF 臂 · 夹爪 · 升降立柱       │
│ 交互层 │ 360° 相机 · 云台变焦 · 6 麦阵列 · 10.1" 屏 · 扬声器        │
│ 能源层 │ 48V/24Ah 主电池 · 48V/30Ah 货架电池 · 220V/500W 逆变      │
└────────────────────────────────────────────────────────────────┘
```

## 二、整机规格

## 三、分系统选型

| 分系统 | 选定方案 | 备选 | 决策理由 | 主要风险 |
| --- | --- | --- | --- | --- |
| 底盘 | 四轮独立驱动 + 前支撑摆臂 | 差速两轮、麦克纳姆轮 | 四轮独立可原地转向、越障强、成本可控；麦轮贵且怕脏 | 悬挂调校工作量大 |
| 爬楼 | 行星轮组（3 叶）+ 前摆臂辅助 | 摆臂履带、轮腿、伸缩腿 | 行星轮对台阶尺寸宽容、结构简单；履带伤地板且慢 | 下楼冲击、转角通过性 |
| 机械臂 | 6DOF 协作臂，负载 5kg，臂展 750mm | 7DOF 冗余臂、SCARA | 6DOF 够用且便宜一半；7DOF 留给 V2 | 绝对精度不足，需视觉伺服 |
| 末端 | 二指电动夹爪 + 快换法兰 | 三指灵巧手、吸盘 | 80% 任务是夹取与按压；快换便于 V2 换头 | 插线类需柔顺，需 RCC 或力控 |
| 升降 | 电动立柱，行程 600mm | 剪叉、丝杠 | 立柱自锁、断电不下坠、噪音低 | 高度增加影响质心与稳定角 |
| 主感知 | 3D LiDAR + 深度相机 ×2 | 纯视觉、2D 雷达 | 成本与可靠性平衡；纯视觉在弱纹理下不可靠 | 玻璃/强光失效，需冗余 |
| 计算 | Jetson Orin NX 16GB + STM32H7 | 纯 x86 工控机、Orin Nano | 算力够跑视觉伺服，功耗 25W；x86 功耗与散热不可接受 | 供应与散热 |
| 通信 | WiFi6 + 4G 双模，双卡 | 单 4G、5G 专网 | 室内 WiFi、室外 4G，双链路保连通 | 弱网抖动 |
| 电源 | 48V 平台，主电池 + 货架电池可并联 | 24V 平台 | 48V 线损小、电机效率高；与货架 220V 逆变匹配 | 电池安全与认证 |

## 四、软件架构

ROS 2（Humble/Jazzy）为骨架，功能按"安全域 / 实时域 / 智能域"三层隔离：

| 层 | 模块 | 运行位置 | 周期 |
| --- | --- | --- | --- |
| 安全域 | 急停、抱闸、限速、碰撞检测、围栏 | STM32（独立） | 1 kHz |
| 实时域 | 底盘运动学、臂伺服、升降控制、里程计 | STM32 + Orin RT | 100–1000 Hz |
| 智能域 | SLAM、导航、目标检测、视觉伺服、语音 | Orin（GPU） | 10–30 Hz |
| 接管域 | 视频编码、WebRTC、指令通道、状态同步 | Orin + 云 | 30–50 Hz |
| 云端 | 设备管理、会话、录像、OTA、订单、计费 | 云 | — |

**关键约束**：安全域与智能域**物理隔离**——智能域崩了，安全域仍能停车。这条不是洁癖，是认证与保险的前提。

## 五、远程接管设计（本项目的核心竞争力）

### 5.1 分级自主

| 等级 | 定义 | 典型场景 | V1 支持 |
| --- | --- | --- | --- |
| L0 | 全人工遥操作 | 首次进陌生环境、复杂插拔 | ✅ |
| L1 | 人工给目标，机器执行 | "去客厅"、"拿那个箱子" | ✅ |
| L2 | 机器自主，人监督 | 定点巡逻、自动回充、巡航 | ✅ |
| L3 | 机器自主，异常才找人 | 园区巡检、固定路线配送 | ⚠️ V1.5 |
| L4 | 全自主 | 全自主上门 | ❌ 不做 |

**产品主张**：卖 L1–L2 的体验，用 L0 兜底。用户感受到的是"它自己会去"，实际是"人给意图、机器执行、必要时人接管"。

### 5.2 链路设计

- **双通道**：媒体走 WebRTC（H.264/AV1，0.5–8 Mbps 自适应）；控制走 DataChannel（50 Hz，带 seq + 时间戳）。
- **弱网策略**：分层码率、关键帧按需请求、FEC 前向纠错、抖动缓冲自适应（30–120 ms）。
- **预测显示**：本地做 dead-reckoning，屏幕上同时画"预测位姿"与"实际位姿"两个光标，操作者能感知延迟而不至于撞墙。
- **降级顺序**：1080p30 → 720p20 → 480p15 → 仅指令（无视频）。任何一级都不允许"卡住不动"。

### 5.3 共享控制（解决时延的根本手段）

| 操作 | 人的职责 | 机器的职责 | 本地闭环周期 |
| --- | --- | --- | --- |
| 移动 | 指方向、给速度上限 | 避障、平滑、防倾覆 | 50 Hz |
| 抓取 | 框选目标 | 位姿估计、接近、闭合、力控 | 30 Hz 视觉伺服 |
| 插拔 | 指定端口 | 孔位检测、柔顺对准、力觉搜索、失败重试 | 100 Hz 力控 |
| 按键 | 指定按钮 | 末端对准、恒力按压 | 100 Hz |

**核心思想**：把"需要 100 ms 内反应"的部分全部下沉到本体，云端只传"意图"。这是 4G 公网能做精细操作的唯一办法。

## 六、安全设计

| 机制 | 实现 | 验证 |
| --- | --- | --- |
| 硬件急停 | 常闭回路直接切电机使能，不经软件 | 示波器测 ≤100 ms |
| 失电抱闸 | 断电即抱死，臂不下坠、轮不溜坡 | 断电跌落测试 |
| 力矩限幅 | 电流环限幅 + 关节力矩传感 | 假人碰撞测试 |
| 碰撞检测 | 电流突变（20 ms）+ 安全触边（双路） | 50 N 力台 |
| 防倾覆 | IMU 倾角 >15° 降速、>25° 停机、>35° 支腿展开 | 斜坡台架 |
| 地理围栏 | 电子围栏 + 楼梯口/阳台禁入区 | 场景测试 |
| 心跳看门狗 | 10 Hz 心跳，丢 3 帧降速，丢 1 s 停车 | 断网注入 |
| 双人复核 | 入室/搀扶类操作需第二人在线确认 | 流程审计 |
| 黑匣子 | 全量指令与传感器日志本地加密留存 30 天 | 抽查 |

## 七、数据与隐私架构

| 原则 | 实现 |
| --- | --- |
| 默认不留存 | 视频仅实时传输，不落盘；用户主动开启才录 |
| 端到端加密 | DTLS-SRTP + 应用层 AES-256；密钥按会话轮换 |
| 本地优先 | 人脸/语音等敏感推理在端侧完成，不上传原始数据 |
| 物理断网 | 机身硬件开关，一键切断 4G/WiFi 并亮灯提示 |
| 分级授权 | 家庭成员 / 远程工程师 / 客服，三级权限与时效 |
| 儿童模式 | 不录音、不录像、不做人脸识别，仅语音互动 |
| 可追溯 | 谁在什么时间接管了哪台设备，全链路审计日志 |
