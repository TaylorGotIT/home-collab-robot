# 02 · 场景与需求

> 需求不是功能列表，是"谁在什么情况下愿意为什么付钱"。本文件把六个真实场景拆成可验收的剧本，并明确写出**我们不做什么**。

## 一、三类用户，三种诉求

| 角色 | 是谁 | 真实诉求 | 付费意愿 | 决策权 |
| --- | --- | --- | --- | --- |
| **付费方** | 异地工作的子女（30–45 岁） | "我不在场，但我想知道、想帮上" | 高（1000–1500 元/月可接受） | 有 |
| **使用者** | 老家老人（65–85 岁）、孩子 | "别太复杂，别像个监视器" | 无（怕花钱、怕被监控） | 否决权 |
| **B 端客户** | 宽服商/运营商装维部门、园区物业 | "单次成本降下来，投诉别增加" | 高（按单/按台结算） | 有 |

**关键洞察**：家庭场景里，付费方和使用者不是同一个人。产品必须同时满足"子女觉得有用"和"老人不反感"。这一条否决了很多"功能很酷但老人抵触"的设计（例如头顶云台跟拍、全天录像）。

## 二、六个场景剧本

### S1 · 每日探望（视频陪伴）

| 项 | 内容 |
| --- | --- |
| 触发 | 子女在 App 上一键"回家看看"；或老人语音"呼叫小明" |
| 流程 | ① 机器人从充电座自主前往客厅 → ② 找到人（人脸/声源）并调整视角 → ③ 建立双向视频 → ④ 可远程移动到厨房/阳台看一圈 → ⑤ 结束自动回充 |
| 成功标准 | 从发起到看到人 ≤60 s；通话 10 分钟内不断流；老人无需任何操作 |
| 失败降级 | 找不到人 → 播报"我到客厅了，您在哪个房间？"；网络差 → 降到 480p 保连通；连续 3 次失败 → 转手机视频 |
| 依赖能力 | C-01, C-02, C-03 |

### S2 · 家电与手机求助

| 项 | 内容 |
| --- | --- |
| 触发 | 老人打电话说"电视又没台了"；子女远程发起"协助" |
| 流程 | ① 机器人到电视/路由器旁 → ② 云台相机对准设备面板与遥控器 → ③ 远程接管，用机械臂按键/递遥控器 → ④ 全程录像存证（本地，7 天） |
| 成功标准 | 15 分钟内解决；无需老人动手；操作有记录可回溯 |
| 失败降级 | 机械臂够不到 → 语音指导老人按哪个键（屏幕高亮箭头）；仍失败 → 转人工上门 |
| 依赖能力 | C-03, C-04, C-05 |
| 备注 | **"全自主操作手机触屏"不在 V1 范围**——手机触屏需要专用末端与亚毫米定位，V3 再评估 |

### S3 · 搀扶起身（最高风险场景）

| 项 | 内容 |
| --- | --- |
| 触发 | 老人从沙发/床边起身困难，主动呼叫；或子女通过视频看到 |
| 流程 | ① 机器人移动到侧面，放下支撑臂/扶手 → ② 语音确认"我要扶您了，请抓住扶手" → ③ 力控上升，限速 20 mm/s，限力 150 N → ④ 老人站稳后撤手 → ⑤ 全程录像 + 事件日志 |
| 成功标准 | 辅助站立成功；无跌倒；老人主观"有支撑感" |
| 失败降级 | 检测到异常下拉力 >200 N 或倾角突变 → 立即停止并放低；同时呼叫紧急联系人 |
| **硬性前提** | **必须有人在场（家人或护工）；不适用于完全失能老人；不承担转移/抱起** |
| 依赖能力 | C-08（V2 交付，不阻塞 V1） |

> 这一条写在这里，是为了让所有人（销售、法务、投资人）看到同一句话：**我们卖的是"辅助站立"，不是"照护替代"**。

### S4 · 取快递

| 项 | 内容 |
| --- | --- |
| 触发 | 快递到驿站/门口，子女远程下单"去取 3 号柜" |
| 流程 | ① 出户 → ② 电梯（人工/呼梯）→ ③ 到驿站，出示取件码（屏幕）→ ④ 抓取包裹放货架 → ⑤ 返回 |
| 成功标准 | 30 分钟内往返；包裹无损；全程可追踪 |
| 失败降级 | 驿站人多/排队 → 语音说明并等待；包裹超重（>10kg）→ 拒取并通知 |
| 依赖能力 | C-02, C-04, C-06 |
| 备注 | 需要与物业/驿站建立"机器人取件"流程，属运营工作而非技术工作 |

### S5 · 上门安装路由器（第一期现金牛）

| 项 | 内容 |
| --- | --- |
| 触发 | 装维系统派单 → 调度中心指派最近机器人 + 一名远程工程师 |
| 流程 | ① 机器人到达小区/写字楼 → ② 客户或物业开门，机器人进入（**必须有人在场**）→ ③ 远程工程师通过 360 相机确认现场 → ④ 机器人放下路由器/光猫，插电源 → ⑤ 插网线（视觉伺服 + 柔顺，允许 3 次重试）→ ⑥ 插 console 线/USB → ⑦ 远程工程师配置、测速、拍照存档 → ⑧ 客户签字/扫码确认 → ⑨ 离开 |
| 成功标准 | 单均 ≤25 分钟；一次成功率 ≥85%；客户满意度不低于人工 |
| 失败降级 | 插线连续 3 次失败 → 转为"语音指导客户插线"（客户动手 30 秒）；仍失败 → 转人工，机器人只承担运输与视频 |
| 依赖能力 | C-03, C-04, C-09 |
| 备注 | **这是"人机协同"而非"无人"**：远程工程师是主角，机器人是"到场的手和眼"。承认这一点，才有 85% 的可行性 |

### S6 · 园区巡检与夜间值守

| 项 | 内容 |
| --- | --- |
| 触发 | 定时任务（每 2 小时一圈）或异常告警联动 |
| 流程 | 按预设路线巡航 → 采集图像/热成像（选配）→ 异常上报 → 远程接管复核 |
| 成功标准 | 路线覆盖率 100%；异常识别召回率 ≥90%；单次充电覆盖 8 小时 |
| 失败降级 | 定位丢失 → 沿墙低速返航；网络中断 → 本地继续巡航并缓存 |
| 依赖能力 | C-02, C-03, C-12 |

## 四、不做清单（同样重要）

| # | 不做 | 原因 |
| --- | --- | --- |
| N-1 | 抱起/转移失能老人 | 负载、平衡、责任三重不可控，属医疗器械/康复辅具监管范畴 |
| N-2 | 无人在场的搀扶 | 一旦跌倒无人兜底，法律与伦理风险不可接受 |
| N-3 | 公共道路/机动车道行驶 | 无明确法规依据，事故责任无法界定 |
| N-4 | 独自进入无人住户家 | 财产与人身纠纷无法自证，必须有人在场 |
| N-5 | 无电梯高层独自爬楼 | 楼梯转角、连续楼层、下行风险叠加 |
| N-6 | 操作明火/燃气/高压/刀具 | 绝对禁止，写进固件级限制 |
| N-7 | 替代监护人做照护决策 | 产品定位是"辅助工具"，不是"看护人" |

## 五、非功能需求（NFR）

| 类别 | 指标 | 目标值 | 验收方式 |
| --- | --- | --- | --- |
| 质量 | 整备质量 | ≤75 kg（含货架电池） | 称重 |
| 续航 | 混合工况 | ≥4 h；货架电池叠加 ≥6 h | 实测 3 轮 |
| 通过性 | 爬楼 | 坡度 ≤30°，单级 ≤180mm，≤6 min/层 | 2 栋真实楼栋 ×20 次 |
| 通过性 | 门槛/地毯 | 门槛 ≤30mm，长毛地毯可通行 | 实测 |
| 实时性 | 端到端视频时延 | P95 ≤200 ms（4G） | 外场 100 次采样 |
| 实时性 | 控制指令时延 | P95 ≤150 ms（局域网） | 同上 |
| 可靠性 | MTBF | ≥500 h | 加速寿命 + 现场 |
| 可靠性 | 连续运行 | 500 h 无致命故障 | 老化台 |
| 操作 | 抓取成功率 | ≥95%（已知物体、结构化摆放） | 200 次抓取 |
| 导航 | 定位精度 | ±5 cm；重复到点 ±10 cm | 标定场 |
| 交互 | 语音唤醒率 | ≥95%（3 m、安静）；≥85%（电视开启） | 200 次 |
| 交互 | 噪音 | 巡航 ≤55 dB(A) @1m | 声级计 |
| 环境 | 防护 | IP54（室内）；货架 IPX3 | 淋雨/粉尘 |
| 安全 | 急停响应 | ≤100 ms 断电停机 | 示波器 |
| 安全 | 碰撞检测 | 接触力 ≥50 N 或电流突变 20 ms 内停机 | 力台 |
| 成本 | 单台成本 | 量产 ≤4.5 万元 | BOM 核算 |
| 隐私 | 视频留存 | 默认不留存；本地加密 7 天可关 | 代码审计 + 渗透测试 |

## 六、KPI 定义（试点阶段唯一口径）

| KPI | 定义 | 目标（M18 试点） | 当前 |
| --- | --- | --- | ---: |
| 任务成功率 | 一次派单内完成且无需人工到场的比例 | ≥85%（工作场景）/ ≥70%（家庭） | — |
| 首次接管成功率 | 远程工程师 5 分钟内建立可用接管的比例 | ≥95% | — |
| 单机日均单量 | 有效完成订单 / 在运营天数 | ≥2.5 | — |
| 平均单均时长 | 到场到离场 | ≤25 min | — |
| MTBF | 累计运行时长 / 故障次数 | ≥500 h | — |
| 客户 NPS | 试点客户推荐意愿 | ≥30 | — |
| 投诉率 | 投诉单 / 总单 | ≤2% | — |

> 这些 KPI 不是"技术指标"，而是"能不能卖"的指标。技术团队按 NFR 干活，项目按 KPI 验收。
