# ADR-0002 · 遥操作采用"分层 + 共享控制"，而非纯视频遥操作

- **状态**：已接受
- **日期**：2026-11
- **决策人**：项目组

## 背景

4G 公网下，端到端时延预算为 150–240 ms（采集 33 + 编码 20 + 上行 55 + 中转 10 + 下行 55 + 解码 23）。而人体对直接遥操作的可接受上限约 100–150 ms。

纯视频遥操作（"看画面 → 摇杆 → 等反馈"）在 200 ms 以上会出现明显过冲与振荡，无法完成插网线、按键这类精细动作。

## 决策

**三层分工**：

1. **云端**只传"意图"：目标点、目标物体、动作类型。
2. **本体**执行闭环：视觉伺服（30 Hz）、力控（100 Hz）、避障（50 Hz）。
3. **人**负责判断与兜底：选择目标、处理异常、必要时接管为 L0。

配套设计：

- 预测显示（dead-reckoning 双光标），让操作者感知延迟而不至于撞墙。
- 关键动作允许"失败重试 3 次"，把成功率从"一次成功"变成"最终成功"。
- 5G 专网作为高端选项（时延可降到 60–110 ms），不作为默认。

## 代价

1. 本体算力必须够（Jetson Orin NX 级，成本 5,800 元），不能省成 MCU + 云。
2. 算法团队必须具备视觉伺服能力，招聘难度高于"会调 WebRTC 的人"。
3. 验收指标从"视频清晰度/延迟"变成"任务成功率"，测试成本更高。

## 替代方案

| 方案 | 为什么没选 |
| --- | --- |
| 纯遥操作 + 5G 专网 | 客户现场不一定有 5G；专网成本与部署周期不可控 |
| 全自主（无接管） | 3 年内做不到，且异常处理无解 |
| 本地操作员（人到现场） | 那就不是机器人项目了，成本等于外包 |

## 影响

- BOM：必须保留 Orin NX 级算力（占量产成本 13.8%）。
- 团队：算法与软件占比不低于 40% 预算。
- 产品：对外话术必须是"它自己会做，必要时我们接管"，而不是"我们遥控它"。
