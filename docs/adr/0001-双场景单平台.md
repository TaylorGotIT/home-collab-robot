# ADR-0001 · 采用"双场景、单平台"策略

- **状态**：已接受
- **日期**：2026-11
- **决策人**：项目组

## 背景

需求方同时提出两类场景：家庭互动（陪老人、孩子、家电协助）与工作协作（上门装路由器、园区巡检）。两者对机器人的要求差异很大：

| 维度 | 家庭 | 工作 |
| --- | --- | --- |
| 环境 | 非结构化、狭窄、有儿童与宠物 | 半结构化、有明确作业点位 |
| 验收 | 主观（老人满意、子女放心） | 客观（单量、时长、成功率） |
| 付费 | 月费 3,200 元上限 | 单次 300–500 元，可算 ROI |
| 责任 | 极高（人身安全） | 中（财产为主） |

若同时开发两套硬件，预算需翻倍（约 5,000 万），且团队精力分散。

## 决策

**一套硬件平台、两套软件配置**：

- 硬件：同一底盘 + 臂 + 货架 + 感知，家庭版减配（去爬楼、去 RTK、降电池）。
- 软件：工作版强调"接管 + 工单 + 留证"；家庭版强调"陪伴 + 隐私 + 易用"。
- 节奏：先工作场景（V1.0，M26），再家庭场景（V1.5，M32）。

## 代价

1. 家庭版硬件成本被工作版的配置拖着走（例如 48V 大电池、RTK 在家庭场景是浪费）。
2. 两套软件的测试矩阵翻倍，QA 人力要多 2 人。
3. V1.0 的品牌形象会被"装路由器的机器人"定义，对家庭市场是负担（需独立子品牌）。

## 替代方案

| 方案 | 为什么没选 |
| --- | --- |
| 只做家庭 | 付费方模糊、验收主观、责任重，现金流撑不到量产 |
| 只做工作 | 放弃最大的差异化（情感价值），长期护城河弱 |
| 两套硬件并行 | 预算翻倍、团队分散，26 个月内做不出来 |

## 影响

- 预算：2,495 万（单平台）而非 5,000 万（双平台）。
- 排期：家庭版顺延 6 个月，但风险大幅降低。
- 组织：需要一个"平台组"（硬件共用）与两个"场景组"（软件分叉）。
