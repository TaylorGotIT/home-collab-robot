# 07 · 风险登记册

> 一条原则：**风险不是列出来就算管了，必须有"早期信号"和"触发后的动作"。**
> 本表 14 项，其中 5 项为"能否立项"级别，见第四节深挖。

## 二、Top 5 深挖

### R-02 · 遥操作时延（最可能让产品"不好用"）

| 项 | 内容 |
| --- | --- |
| 为什么排第一 | 它不像爬楼会翻车那样显眼，但会让产品"能用却难用"，试点数据会悄悄崩掉 |
| 量化 | 端到端预算 150–240ms；人体可接受上限 100–150ms；**缺口 50–100ms** |
| 根因 | 4G 公网上行带宽与抖动不可控，不在我们手里 |
| 缓解 | ① 共享控制把"反应"下沉到本体；② 预测显示降低操作者认知负担；③ 关键客户可选 5G 专网（时延降到 60–110ms） |
| 残留风险 | 偏远地区 4G 上行 <2Mbps 时，只能做 L0 粗操作，精细任务转人工 |
| 验证点 | G2：外场 100 次采样，P95 ≤200ms 才放行 |

### R-01 · 爬楼可靠性（最可能让项目"延期"）

| 项 | 内容 |
| --- | --- |
| 为什么排第一 | 它是机械问题，迭代周期长（开模、加工、装配各 2–4 周），一旦返工就是季度级延误 |
| 量化 | 目标 500 次循环成功率 100%；真实楼栋 20 次；单层 ≤6 分钟 |
| 根因 | 国内老楼踏步高度 150–180mm 不统一、转角平台窄、扶手位置各异 |
| 缓解 | ① 行星轮 + 前摆臂，对踏步宽容；② 把"爬楼"做成**可插拔选配模块**，V1 可先不带爬楼交付；③ 建立"楼栋适配清单"，销售端先筛楼 |
| 残留风险 | 极窄转角（<1.1m）仍可能过不去，需人工介入 |
| 验证点 | G2：2 栋真实楼栋 ×20 次全部通过 |

### R-03 · 搀扶安全（最可能让公司"赔钱"）

| 项 | 内容 |
| --- | --- |
| 为什么排第一 | 一次事故足以摧毁品牌与现金流，且法律责任可能超出产品范畴 |
| 量化 | 竖直辅助力 ≤150N、速度 ≤20mm/s、异常拉力 >200N 立即停止 |
| 缓解 | ① 产品定义写死"有人监护"；② 双人复核（远程 + 现场）；③ 失电抱闸 + 机械限位；④ 产品责任险（保额 ≥1000 万）；⑤ 全程录像存证 |
| 残留风险 | 老人自行误用（无监护时强行启动）→ 固件级检测"无人确认则拒绝执行" |
| 决策点 | 是否在 V1 就交付此功能？**建议 V2 交付，且单独定价、单独免责** |

### R-07 · 客户是否让机器人进门（最可能让商业"证伪"）

| 项 | 内容 |
| --- | --- |
| 为什么排第一 | 这是纯社会接受度问题，技术再好也解决不了 |
| 量化 | 试点拒单率 ≤40%；转化率 ≥50% 才算跑通 |
| 缓解 | ① "门口交付 + 客户协助 2 分钟"降低心理门槛；② 先做写字楼/园区（有物业、有监控、有前台）；③ 全程录像可回溯，给客户"可查"的安全感 |
| 残留风险 | 独居老人家政场景可能长期不接受，需靠"子女在场远程开门"绕过 |
| 验证点 | G4：120 单里拒单率与转化率 |

### R-08 · 单量与人力配比（最可能让生意"不赚钱"）

| 项 | 内容 |
| --- | --- |
| 为什么排第一 | 敏感性分析显示它是成本第一变量（3.5 倍差距），远超硬件价格 |
| 量化 | 目标日均 2.5 单、1 人管 4 台；低于 1.5 单 / 1 人管 3 台则回本期 >17 个月 |
| 缓解 | ① 调度算法做"一人多机"；② 低峰期把机器人转做巡检/陪伴，提高利用率；③ 与宽服商签"保底单量"协议 |
| 残留风险 | 订单分布不均（早晚高峰），需要"错峰复用"运营设计 |
| 验证点 | G4：单机日均单量 ≥2.0 |
