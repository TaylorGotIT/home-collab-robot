# 00 · 项目概览（一页纸）

> 给没有时间读全文的人。所有结论的论证在后续章节，所有数字来自 `data/*.csv`。

## 一句话结论

**方向成立，但必须降维定义。** 把目标从"全自主家政机器人"改成"**可远程接管的轮式移动操作机器人**"，把家庭与工作两个场景按"付费意愿 ÷ 技术难度"排序、分两期落地，项目可以在 **26 个月**进入量产，总投入 **2,495 万元**，单台成本从原型 **10.6 万**降到量产 **4.1 万**。

## 六条判断

| # | 判断 | 依据 |
| --- | --- | --- |
| 1 | 六类需求里 **四类现在就能做** | 视频互动、室内移动、远程接管、简单抓取——都是成熟技术的组合，不是新发明 |
| 2 | **两类必须限定条件** | 搀扶（限"有人监护下辅助站立"，不做抱起转移）、爬楼（限 ≤30°、单级 ≤180mm、速度 3-6 分钟/层） |
| 3 | **两类三年内不做** | 全自主上门（进门/异常处理无解）、上街买菜（法规空白 + 安全责任无法兜底） |
| 4 | **工作场景先上，家庭场景后上** | 网络安装付费方明确、动作标准化、容错率高；家庭场景情感价值高但验收标准模糊、责任重 |
| 5 | **成本不是瓶颈** | 硬件降 20% 只让单次成本降 8%；"一人管几台"能让单次成本差 2 倍 |
| 6 | **合规是硬门槛** | SRRC + CCC/EMC + 电池 + 数据合规 + 产品责任险，预算 90 万、周期 6 个月，必须前置 |

## 需要拍板的五件事

1. **产品定义**：是否接受"远程接管为主、自主为辅"的定位？（这决定 80% 的技术选型）
2. **首发场景**：是否以"网络上门安装"作为第一个商业化场景？（决定 B 样试点地点与 BD 打法）
3. **预算**：2,495 万元是否按 26 个月分期批准？建议按 4 个 gate 分批释放（每 gate 释放 25%）。
4. **团队**：机械、嵌入式、感知算法、遥操作四条线必须自有，机械臂与底盘可外购/外协。
5. **责任边界**：是否接受"搀扶类功能仅限有人监护、并写入用户协议"？这是产品能不能做的前置条件。

## 三个必须接受的前提

- **不追求全自主**。产品价值是"人在环"的效率放大，不是取代人。
- **不追求一次到位**。爬楼、搀扶、手机操作三类能力放在 V2/V3，不阻塞 V1 上市。
- **不回避责任**。所有涉及老人、儿童、上门入室的功能，都要有书面边界、保险兜底和可追溯日志。
